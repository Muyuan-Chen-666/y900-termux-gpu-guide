## 1. 它想做什么

在已经跑起来的 Termux:X11 `:8` 桌面上，再起一个 `x11vnc`，把同一个桌面共享给 Android 上的 AVNC 客户端：

```text
XFCE (:8) ──┬── Termux:X11 → gpu-test 窗口（本地显示，已可用）
            └── x11vnc → 127.0.0.1:5901 → AVNC 客户端（未验证）
```

具体命令（设备现装管理器原文）：

```text
x11vnc -display :8 -rfbauth /home/desktop/.vnc/passwd \
       -localhost -listen 127.0.0.1 -no6 -rfbport 5901 \
       -forever -shared -noshm -noxdamage -noxrecord \
       -wait 20 -defer 10
```

客户端一侧通过 `am start` 打开 `vnc://127.0.0.1:5901/?...`，若存在
`~/.config/ubuntu-manager/initial-password` 还会把密码拼进 URI。

## 3. 为什么不能作为默认入口

1. **未验证**：没有成功的端到端记录，默认安装会把用户带进已知失败路径；
2. **会阻断启动**：该管理器的 `start` / `x11` 冷启动可能先尝试 VNC，失败就报错，看起来像 GPU 坏了；
3. **多一层攻击面**：多开一个 VNC 监听端口，还要处理密码文件与监听地址；
4. **不是 GPU 必需**：GPU 管线只需要 X11 显示，AVNC 只是「远程看这个桌面」的另一种方式；
5. **不能替代 X 服务器**：即使 AVNC 修好，后台仍然需要 `termux-x11 :8`。

## 4. 如果将来要继续这条支线

需要独立、完整地验证以下每一项，并记录证据：

- [ ] RFB 握手成功（`RFB 003.008` 之类）；
- [ ] 密码认证成功（VNC 密码，非 sudo 密码）；
- [ ] 画面持续更新（不是静止首帧）；
- [ ] 鼠标/键盘输入可用；
- [ ] `vnc-stop` 能及时退出，不留僵尸进程；
- [ ] 用 `ss -ltnp` / `netstat` 确认**只**监听预期的 `127.0.0.1:5901`，没有 `[::]:5900` 之类意外端口；
- [ ] 断开 AVNC 后，本地 `gpu-test` 窗口仍正常。

在此之前，本仓库不会把 AVNC 写进默认流程，也不会声称它可用。

---

## 5. 安全提醒

- 不要把 `.vnc/passwd`、`initial-password`、`authorized_keys` 或任何私钥提交到仓库；
- 不要把 VNC 密码复用为 sudo 密码；
- 不要在公网暴露 5900/5901；
- 若曾把密码写进 shell 历史或日志，分享前清理。
