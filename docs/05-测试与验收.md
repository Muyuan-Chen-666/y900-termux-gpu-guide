# 05 · 测试与验收

---

## 1. 三个测试入口

桌面已启动（`ubuntu-manager status` 显示运行中）后，在**普通 Termux** 执行：

```sh
bash scripts/run-gpu-test.sh smoke     # 默认，45 秒限时三场景 glmark2
bash scripts/run-gpu-test.sh gears     # 交互式 glxgears，关窗口或 Ctrl+C 结束
bash scripts/run-gpu-test.sh compare   # 先软件渲染、再 GPU 各跑一次 glmark2
```

等价于直接调用管理器：

```sh
ubuntu-manager test                   # 60 秒限时三场景 glmark2
ubuntu-manager run glxgears -info -geometry 800x600
```

三个场景固定为 `build` / `texture` / `shading`，每个 `duration=5`，窗口 `800x600`。

---

## 2. 怎么看输出：先看 renderer

### 2.1 GPU 路径（正确）

```text
GL_VENDOR:      Mesa
GL_RENDERER:    virgl (ANGLE (ARM, Vulkan 1.3.278 (Mali-G925-Immortalis MC1...)
GL_VERSION:     2.1 Mesa 25.2.8-0ubuntu0.24.04.4
```

`glxgears -info` 版本：

```text
GL_RENDERER   = virgl (ANGLE (ARM, Vulkan 1.3.278 (Mali-G925-Immortalis MC1...)
GL_VERSION    = 2.1 Mesa 25.2.8-0ubuntu0.24.04.4
GL_VENDOR     = Mesa
```

**判读规则：** 同时出现 `virgl`、`ANGLE`、`Mali` 才算走了本链路。

### 2.2 软件路径（降级）

```text
GL_RENDERER:    llvmpipe (LLVM 20.1.2, 128 bits)
GL_VERSION:     4.5 (Compatibility Profile) Mesa 25.2.8-0ubuntu0.24.04.4
```

出现 `llvmpipe` 或 `softpipe`，说明**这一次**程序走的是 CPU 软件绘图。常见原因见 [06-常见问题](06-常见问题.md)。

> 仅看到 `GL_VENDOR: Mesa`、设置了环境变量、或窗口能打开，都**不足以**证明硬件加速 —— VirGL 的 `GL_VENDOR` 本来就是 Mesa。

### 2.3 字符串截断不是错误

`Mali-G925-Immortalis MC1...` 末尾的 `...` 是历史输出原样截断，不要当成错误，也不要据此推断核心数量。

## 3. 验收清单

一次合格的验证至少包含：

- [ ] `glmark2` 的 `build`、`texture`、`shading` 三场景都打印结果；
- [ ] 进程退出码 `0`（不是被 `timeout` 杀掉）；
- [ ] 图形窗口内容真实可见、持续更新（不是黑屏或静止首帧）；
- [ ] renderer 含 `virgl` / `ANGLE` / `Mali`，不含 `llvmpipe`；
- [ ] 重复执行 `ubuntu-manager start` 不会多开 XFCE；
- [ ] 停止后再冷启动，socket 能重新建立。

### 退出码

| 退出码 | 含义 |
|---|---|
| `0` | 正常结束 |
| `124` | 被外部 `timeout` 终止。`glxgears` 由外部限时结束时出现 `124` 属正常；`glmark2` 三短场景本应在 45 秒内自己结束，若也是 `124` 需排查 |
| 其它 | 视为异常，查日志 |

## 4. 性能结论的边界（重要）

历史两次对照（详见 [08-历史验证记录](08-历史验证记录.md)）：

| 日期 | 软件（llvmpipe） | GPU（virpipe/Mali） |
|---|---|---|
| 2026-10-17 | 141 | 140 |
| 2026-10-20 | 96 | 94 |

**结论：短测没有证明整体提速。** 原因与限制：

1. `glmark2` 提示 `GLX does not support GLX_EXT_swap_control` / `Failed to set swap interval`，结果可能被刷新率截顶；
2. 10-20 那次存在其他 Android 图形负载与后台调度影响；
3. 两次的绝对分数都不同（环境不固定），只能同场对照，不能跨天比较；
4. `xrandr` 报的名义频率（如 `29.90`）**不能**直接当作真实屏幕呈现帧率；
5. 该管线把 OpenGL 命令经 Unix socket 转给 VirGL 再转 ANGLE，**存在额外开销**，低负载场景下与 CPU 软件渲染接近是正常现象。

如需声称「更快」，必须在**同一前台显示、同一分辨率、同一窗口大小、同一负载**下对照，并实际测量显示/交互延迟，不能只看 `glxgears` 的 FPS。

## 5. 已知测试限制

| 现象 | 说明 |
|---|---|
| `glxinfo -B` 报 `X_GetImage` / `BadMatch` | 该 Virpipe 路径的已知兼容问题；**不要**把 `glxinfo` 当唯一验收，用 `glmark2` / `glxgears` |
| 浏览器、VS Code 有各自兼容开关 | 例如 VS Code 的 `--disable-gpu` 仍会生效；桌面启动器可能覆盖 GPU 环境变量 |
| 视频解码 | 本链路只覆盖 OpenGL 绘图，**不包含**硬件视频解码验证 |
| 多显示器 / 分辨率切换 | 仅验证过 `:8` 单显示；改分辨率用 `ubuntu-manager size WxH` 或在 Termux:X11 设置里改 |
