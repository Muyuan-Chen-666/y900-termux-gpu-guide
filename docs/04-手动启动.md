# 04 · 手动启动管线（排除管理脚本干扰）

用于：

- 管理器的 AVNC 分支干扰排查；
- 确认问题出在 X11、VirGL 还是桌面；
- 做一次不依赖 XFCE 的最小 GPU 绘图验证。

> **只在确认 `:8` 与 `y900-gpu-vtest` 没有其他使用者时执行。** 桌面已经起来就复用管理器，不要重复启动。

---

## 1. 启动两个服务（普通 Termux）

```sh
mkdir -p "$HOME/.local/state/y900-manual-test"

nohup virgl_test_server_android --angle-vulkan \
  --socket-path "$TMPDIR/y900-gpu-vtest" \
  > "$HOME/.local/state/y900-manual-test/virgl.log" 2>&1 < /dev/null &
echo $! > "$HOME/.local/state/y900-manual-test/virgl.pid"

nohup termux-x11 :8 -tag gpu-test -extension MIT-SHM \
  > "$HOME/.local/state/y900-manual-test/x11.log" 2>&1 < /dev/null &
echo $! > "$HOME/.local/state/y900-manual-test/x11.pid"
```

注意：

- `--socket-path` 必须是 Termux 的 `$TMPDIR/y900-gpu-vtest`；
- `-tag gpu-test` 只是窗口标签；`-extension MIT-SHM` 不能省；
- 若这里报「address already in use」，先查 `:8` 与 socket 的现有使用者，不要直接再起一份。

## 2. 核对服务就绪

```sh
test -S "$TMPDIR/y900-gpu-vtest" && echo socket-ok

proot-distro login ubuntu --user desktop --shared-tmp --no-sysvipc -- \
  env DISPLAY=:8 xdpyinfo | head -5
```

`xdpyinfo` 能输出 `name of display: :8`、版本与屏幕信息，说明 X11 通了。**它不证明 GPU 生效。**

## 3. 在 `:8` 上跑三场景 glmark2

```sh
proot-distro login ubuntu --user desktop --shared-tmp --no-sysvipc -- \
  env -u LIBGL_ALWAYS_SOFTWARE -u MESA_GL_VERSION_OVERRIDE \
  -u MESA_GLSL_VERSION_OVERRIDE -u MESA_LOADER_DRIVER_OVERRIDE \
  DISPLAY=:8 GALLIUM_DRIVER=virpipe VTEST_SOCKET_NAME=/tmp/y900-gpu-vtest \
  timeout --kill-after=3s 45s glmark2 --size 800x600 \
  --benchmark build:duration=5 --benchmark texture:duration=5 --benchmark shading:duration=5
```

要点：

- `VTEST_SOCKET_NAME` 在容器内是 `/tmp/y900-gpu-vtest`（`--shared-tmp` 保证同一文件）；
- 显式 `-u` 掉软件渲染/版本覆盖变量，避免被环境「悄悄降级」；
- 45 秒应足够三个 5 秒场景自行结束；若退出码 `124`，说明被 timeout 杀掉，需要排查。

## 4. 打开对应的 Android 窗口

```sh
am start --user 0 -n com.termux.x11/com.termux.x11.MainActivity -d gpu-test
```

若系统阻止后台拉起，手动切到 Termux:X11。**不要因为没有自动跳转就重复创建新桌面。**

## 5. 启动完整 XFCE（可选）

先确认容器里已装 `start-tablet-gpu`（即已执行过 `scripts/restore-x11-baseline.sh`），然后：

```sh
proot-distro login ubuntu --user desktop --shared-tmp --no-sysvipc -- \
  /usr/local/bin/start-tablet-gpu
```

前台运行便于看日志。**不要**在已有 `:8` XFCE 的情况下重复启动。

## 6. 结束与清理

手动方式**没有** `session.json` 管理记录，因此：

- `ubuntu-manager stop` **不能**管理手动创建的 XFCE；
- 退出 XFCE 后，先按 PID 文件核对命令与显示号：

```sh
cat "$HOME/.local/state/y900-manual-test/virgl.pid" "$HOME/.local/state/y900-manual-test/x11.pid"
ps -o pid,args -p "$(cat "$HOME/.local/state/y900-manual-test/virgl.pid")" \
                 -p "$(cat "$HOME/.local/state/y900-manual-test/x11.pid")"
```

- 只对确认过的 PID 发 `TERM`：

```sh
kill -TERM "$(cat "$HOME/.local/state/y900-manual-test/virgl.pid")" \
           "$(cat "$HOME/.local/state/y900-manual-test/x11.pid")"
```

- **不要**停止整机 `proot`、`dbus-daemon` 或所有 X11 显示。

## 7. 手动与基线的差别

| | 手动 | 基线 `ubuntu-manager` |
|---|---|---|
| 服务 PID 记录 | 自己写在 `~/.local/state/y900-manual-test/` | `~/.local/state/y900-gpu/` + `~/.local/state/y900-xfce-gpu/session.json` |
| 停止方式 | 手动核对 PID 后 `kill -TERM` | `ubuntu-manager stop` |
| XFCE 管理 | 无 | PID + start time 校验，防误杀 |
| 适用场景 | 排错、最小验证 | 日常使用 |
