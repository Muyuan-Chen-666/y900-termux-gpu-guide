> 本文原为随 2026-11-09 ZIP 归档发布的交接说明，现按本仓库的目录整理，内容未改变（仅更新了一处文件路径）。可直接整段粘贴给新的 AI 会话。

请读取本仓库（`y900-termux-gpu-guide`），先看根目录 README.md，再检查 SHA256SUMS、scripts 和 metadata。目标是在 Lenovo Y900 的普通 Termux＋Ubuntu ARM64 中复现已验证的 X11/Mali GPU 绘图路径，在 gpu-test 窗口运行 glmark2/glxgears；不要自行切换 GNOME、Root、刷机或替换 Android 原厂 GPU 驱动。

关键事实：

1. 归档日为 2026-11-09，已只读连接实机。当前桌面、VirGL、VNC 均未运行。Ubuntu 容器名 ubuntu、用户 desktop；当前 UID/GID 10309，与 Termux 对应。
2. Termux 是 Google Play 分支，PREFIX=/data/data/com.termux/files/usr；rootfs 在 `$PREFIX/var/lib/proot-distro/containers/ubuntu/rootfs`。不要套用其他 proot-distro 布局或卸载 Termux。
3. 管线：Ubuntu Mesa `GALLIUM_DRIVER=virpipe`＋`VTEST_SOCKET_NAME=/tmp/y900-gpu-vtest` → Termux `virgl_test_server_android --angle-vulkan --socket-path "$TMPDIR/y900-gpu-vtest"` → ANGLE Vulkan → Android Mali-G925。
4. 显示为 `termux-x11 :8 -tag gpu-test -extension MIT-SHM`。PRoot 必须保留 `--shared-tmp --no-sysvipc`。
5. **gpu-test 是窗口标签，不是独立 GpuTest 软件。** 已验证的是 glmark2 和 glxgears；本轮未发现 GpuTest/gputest 可执行文件。如果我要求独立 Geeks3D GpuTest，请另外核对 ARM64 支持，不能说它已安装。
6. `scripts/termux/ubuntu-manager` 是取自设备备份的已验证纯 X11/GPU 基线；`experiments/avnc-unfinished/ubuntu-manager-avnc-unfinished` 才是归档日设备现装管理器，带未完成 AVNC 分支。后者的默认 start/x11 冷启动可能被 VNC 错误阻断，不能混淆。
7. AVNC 实验上次被中断，没有成功认证和画面验证。不要先继续该支线；除非我明确要求 AVNC，否则按 README 恢复/手动验证 X11 基线。
8. 先只读核对连接、容器和依赖。已有镜像时不 remove/reset/reinstall；恢复前保存工作并退出 XFCE，再使用带备份的 `scripts/restore-x11-baseline.sh`。辅助恢复/准备/测试脚本在本轮只通过静态检查，没有在设备执行过。
9. 如获准执行复现，在普通 Termux：基线恢复 → `ubuntu-manager start` → `bash scripts/run-gpu-test.sh smoke`。需看到 virgl/ANGLE/Mali renderer、实际更新的测试图像及 glmark2 正常退出。不以 glxinfo -B 作为唯一验收，它有已知 BadMatch 问题。
10. 历史短测没有证明 GPU 全面更快；不能把绘图 FPS 当作桌面刷新率。保留浏览器和 VS Code 的兼容参数，不为追求数字伪造 GL 版本。

连接：电脑通过 USB ADB 转发 18022→平板 Termux SSH 8022，原 Termux 用户为 `u0_aXXX`（以平板 `whoami` 为准）。用现有电脑授权密钥；归档不含私钥、VNC 密码、API 密钥或 rootfs。无法连接先检查 USB 调试授权、转发和 sshd。
