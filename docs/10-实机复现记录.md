## 2. 执行流程（与文档一致）

1. Fork 上游仓库，克隆到工作区；通过 USB ADB 转发 `18022 → 8022` 连接 Termux 的 SSH（密钥认证）。
2. 用 `git archive` 打包 HEAD 部署到 Termux `$HOME/y900-termux-gpu-guide`，`sha256sum -c` 全部通过、无 CRLF。
3. 安装 Termux 侧依赖（`termux-x11-nightly virglrenderer-android angle-android vulkan-loader-android pulseaudio`）。
4. 容器内执行 [`scripts/prepare-ubuntu.sh`](../scripts/prepare-ubuntu.sh)（传入实际 `<UID>`）。
5. 普通 Termux 执行 [`scripts/restore-x11-baseline.sh`](../scripts/restore-x11-baseline.sh)（带备份，不启动桌面）。
6. `ubuntu-manager start` → `ubuntu-manager status` → [`scripts/run-gpu-test.sh`](../scripts/run-gpu-test.sh) `smoke` / `gears`。

必须保留的兼容参数未做改动：`--shared-tmp --no-sysvipc`、`termux-x11 :8 … -extension MIT-SHM`、`GALLIUM_DRIVER=virpipe`、`VTEST_SOCKET_NAME=/tmp/y900-gpu-vtest`。

## 3. 与作者基线的版本差异及适配（重点）

### 3.1 proot-distro 5.8.0 的 `aid_` 条目占用 Termux UID

**现象：** `prepare-ubuntu.sh` 在创建 `desktop` 用户处失败：

```text
useradd: UID <UID> is not unique
PREP_EXIT=4
```

**原因：** proot-distro **5.8.0**（Python 实现）在 `install` 阶段调用 `register_android_ids_at`，向容器 `/etc/{passwd,shadow,group,gshadow}` 追加形如
`aid_u0_aXXX:x:<UID>:<UID>:Termux:/:/sbin/nologin` 的条目（及若干 `aid_*` 组）。这占用了 `desktop` 必须使用的同一个 Termux UID/GID，导致 `useradd -u <UID> desktop` 冲突。作者的 5.3.0（bash）不产生该冲突。

**判定依据（已核对源码与本机文件）：**

- 该函数仅在 `install` 流程调用，`login` 只读取 `/etc/passwd`，**不会在登录时重新写入** `aid_` 条目；
- 这些 `aid_` 条目 home=`/`、shell=`/sbin/nologin`，不对应任何真实数据；
- 冲突的只是占用 `<UID>` 的那条 `aid_u0_aXXX`；其余 `aid_*` 组为附加组，不参与 UID 冲突。

**处理（已在实机验证）：** 先备份，再移除容器身份文件中的 `aid_` 行，然后重跑 `prepare`。保留 `root` 等系统条目。命令示例（普通 Termux 下）：

```sh
R="$PREFIX/var/lib/proot-distro/containers/ubuntu/rootfs"
BK="$HOME/.local/share/y900-backup/identity-$(date +%Y%m%d-%H%M%S)"; mkdir -p "$BK"
cp -p "$R/etc/passwd" "$R/etc/shadow" "$R/etc/group" "$R/etc/gshadow" "$BK/"
for f in passwd shadow group gshadow; do
  grep -v '^aid_' "$R/etc/$f" > "$R/etc/$f.y900tmp"
  cat "$R/etc/$f.y900tmp" > "$R/etc/$f"     # 原地覆写，保留权限
  rm -f "$R/etc/$f.y900tmp"
done
```

之后重跑 `prepare-ubuntu.sh` 即可。**备选方案：** 直接使用作者验证过的 proot-distro 5.3.x，可避免该冲突。

**结果：** `desktop` 干净创建为 `desktop:x:<UID>:<UID>::/home/desktop:/bin/bash`，
`id desktop` = `uid=<UID>(desktop) gid=<UID>(desktop) groups=<UID>(desktop)`，与作者布局一致。

### 3.2 旧版 Termux:X11 APK 不支持 `-tag`

**现象：** `ubuntu-manager start` 报「GPU 显示服务未就绪」；`~/.local/state/y900-gpu/x11.log` 显示：

```text
Fatal server error:
(EE) Unrecognized option: -tag
```

**原因：** X 服务器本体在 **Termux:X11 的 APK**（`com.termux.x11`）内；companion 包 `termux-x11-nightly` 只提供 wrapper 与 loader，不决定该选项。旧 APK（如 commit `0fff278`）不解析 `-tag`；上游当前 master 的 `cmdentrypoint.cpp` 已支持（解析 `-tag` 参数并调用 `setDocumentTag`）。

**判定依据：** `termux-x11 --help` 中无 `-tag`；`adb shell dumpsys package com.termux.x11` 显示旧 `versionName`。

**处理（已在实机验证）：** 用官方 nightly 的普通 APK 覆盖更新（保留偏好数据）：

```sh
# 官方 nightly 资源：termux-x11-universal-debug.apk
adb install -r termux-x11-universal-debug.apk
```

注意事项：

- 用**普通** `termux-x11-universal-debug.apk`，**不要**用 `sharedUid` 变体（后者是与 Termux 共享 UID 的构建）；
- 旧 APK 若为 debug 签名，可直接原地升级；更新后 `versionName` 形如 `1.03.01-a31042e-09.11.26`，`-tag` 生效。

**结果：** `:8` 正常启动，`termux-x11 :8 -tag gpu-test -extension MIT-SHM` 进程存活，XFCE 正常运行。

> 提示：`x11.log` 为追加日志，历史失败留下的 `Unrecognized option: -tag` 会残留，**不代表当前故障**；以进程是否存活、`xdpyinfo`、renderer 为准。

## 4. 验收结果（本机实测）

renderer（`glmark2` 与 `glxgears -info` 一致）：

```text
GL_RENDERER: virgl (ANGLE (ARM, Vulkan 1.3.278 (Mali-G925-Immortalis MC1...)))
GL_VERSION:  2.1 Mesa 25.2.8-0ubuntu0.24.04.4
```

| 检查项 | 结果 |
|---|---|
| `glmark2` smoke 三场景 | build 88 / texture 98 / shading 107 FPS，Score **96**，退出码 **0**（非 timeout） |

| 冷启动 | `stop` → `start` 后 socket 重建（`socket-ok`） |
| 目视 | `gpu-test` 窗口内齿轮持续转动（维护者确认） |

## 6. 跨屏投放备注

用联想超级互联把 Termux:X11 窗口跨屏投放到电脑显示器时，投放瞬间 Termux:X11 的显示表面会短暂切换/断开；但 **X 服务器与桌面进程不会崩溃**，重新贴回平板上的 `gpu-test` 窗口即可恢复画面；确有需要时用 `ubuntu-manager restart` 干净重建（不要反复新建桌面）。本机实测投放时 glxgears 仍在持续渲染，桌面健康。
