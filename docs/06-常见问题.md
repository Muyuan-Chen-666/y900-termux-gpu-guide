# 06 · 常见问题

按「现象 → 优先检查 → 处理」组织。日志位置见页面底部。

---

## 1. 找不到 `ubuntu-manager`

**检查**

```sh
echo "$PREFIX/bin"
ls -l "$PREFIX/bin/ubuntu-manager"
command -v ubuntu-manager
```

**处理**

- 确认当前是**普通 Termux**，不是容器内；
- 确认执行过 `bash scripts/restore-x11-baseline.sh`；
- `PATH` 缺 `$PREFIX/bin` 时，直接用绝对路径：
  `/data/data/com.termux/files/usr/bin/ubuntu-manager status`。

---

## 2. 打不开 `:8` / Termux:X11 黑屏

**检查**

```sh
pgrep -a termux-x11
ps -o pid,args -p "$(cat ~/.local/state/y900-gpu/x11.pid 2>/dev/null)" 2>/dev/null
tail -40 ~/.local/state/y900-gpu/x11.log
proot-distro login ubuntu --user desktop --shared-tmp --no-sysvipc -- \
  env DISPLAY=:8 xdpyinfo | head -3
```

**处理**

- Termux:X11 APK 与 companion 包是否都装了、版本是否配套；
- `termux-x11` 进程是否真的在跑；
- `--shared-tmp` 是否漏了；
- 系统可能阻止后台拉起窗口，手动切到 Termux:X11，**不要**反复新建桌面。

---

## 3. VTEST socket 连接失败

**检查**

```sh
ls -l "$TMPDIR/y900-gpu-vtest"
ps -o pid,args -p "$(cat ~/.local/state/y900-gpu/virgl.pid 2>/dev/null)"
tail -40 ~/.local/state/y900-gpu/virgl.log
```

**处理**

- 宿主侧路径应是 `$TMPDIR/y900-gpu-vtest`，容器内应是 `/tmp/y900-gpu-vtest`；两者靠 `--shared-tmp` 对齐；
- VirGL 进程是否还活着（PID 文件里的命令必须含 `virgl_test_server_android` 与 `y900-gpu-vtest`）；
- 使用者 UID 是否一致（本机 `desktop` = `10309`，换机后需相符）；
- 旧 socket 文件残留时，确认没有进程占用后再删，不要盲删。

---

## 4. renderer 是 `llvmpipe` / `softpipe`

**检查**

```sh
ubuntu-manager run env | grep -E 'GALLIUM|VTEST|LIBGL|MESA'
```

**处理**

- 是否经 `ubuntu-manager run` / `gpu-shell` 启动？直接在容器里裸跑可能没有 GPU 变量；
- `LIBGL_ALWAYS_SOFTWARE` 或其他 `MESA_*` override 是否被应用启动器、`.bashrc`、桌面项覆盖；
- 该程序的启动器是否自带 `--disable-gpu`（VS Code 常见）；
- 用 `ubuntu-manager software 程序名` 只能**有意**走软件渲染，别混用。

---

## 5. `glxinfo -B` 触发 `X_GetImage` / `BadMatch`

这是该 Virpipe 路径的**已知兼容问题**，不是驱动没装好。

**处理**：改用 `glmark2` / `glxgears` 的实际绘图作为验收依据，不把 `glxinfo` 当唯一标准。

---

## 6. 多出 VNC 错误，但 X11 其实已经起来

**原因**：还在用设备现装的 AVNC 分支管理器（`experiments/avnc-unfinished/`），它的 `start` / `x11` 冷启动可能先尝试起 VNC。

**处理**：恢复本仓库 `scripts/` 的基线管理器。参见 [07-AVNC实验边界](07-AVNC实验边界.md)。

---

## 7. 共享内存 / linker 错误

**处理**

- 保留 `--no-sysvipc`；
- 保留 `-extension MIT-SHM`（即禁用 MIT-SHM）；
- 不要「为了兼容」擅自删掉这些参数，也不要随意加 `LD_PRELOAD` 或替换 Mesa 库。

---

## 8. 程序突然消失

**检查**

- Android 后台限制、内存压力、温度/耗电策略；
- 幻影进程设置（见下）；
- 是否被 `timeout` 杀掉（看退出码 `124`）。

**处理**：先区分「进程被杀」与「脚本丢失」。**不要**直接认定脚本损坏或重装 Termux。

---

## 9. 从 SSH 启动的程序没有图形

**原因**：SSH 会话没有 `DISPLAY`、D-Bus 地址与 GPU 变量。

**处理**

```sh
proot-distro login ubuntu --user desktop --shared-tmp --no-sysvipc -- \
  /usr/local/bin/y900-live-session 程序名
```

或在 Termux 用 `ubuntu-manager run 程序名` / `ubuntu-manager gpu-shell`。

---

## 10. 幻影进程限制

本轮只读值：

```text
activity_manager/max_phantom_processes = null
settings_enable_monitor_phantom_procs = false
```

与历史设置过的 `2147483647` 不同。**`null` 不等于「已取消阈值」**，`monitor=false` 也不取消内存/耗电/温度管理。

- 普通 Termux **无法**写系统设置，需电脑 ADB；
- 修改前另行确认当前系统版本、备份原值、记录回滚方式；
- 不要靠 `.bashrc` 写系统设置。

---

## 11. 无法通过电脑 SSH 连接平板

**检查顺序**

```sh
# 平板（普通 Termux）
sshd
whoami
# 电脑
adb devices -l
adb forward tcp:18022 tcp:8022
ssh -p 18022 -i <本机授权私钥> <平板上的实际用户名>@127.0.0.1
```

- USB 调试授权是否通过；
- `adb forward` 是否建立；
- `sshd` 是否在跑（`pgrep -a sshd`）；
- 用户名以平板 `whoami` 为准，不要硬编码其他设备的 UID。

**本仓库不含任何私钥、`authorized_keys` 或密码。**

## 12. 日志位置

| 日志 | 路径 |
|---|---|
| 桌面 | `~/.local/state/y900-xfce-gpu/desktop.log` |
| VirGL | `~/.local/state/y900-gpu/virgl.log` |
| X11 | `~/.local/state/y900-gpu/x11.log` |
| 一次查看全部 | `ubuntu-manager logs`（`tail -30`） |

> 本仓库只附**选定的测试输出**，不打包全部运行日志，避免带入应用 token、账号信息或本地路径。
