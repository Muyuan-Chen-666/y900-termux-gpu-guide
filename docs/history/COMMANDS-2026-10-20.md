# Y900 当前指令：统一 GPU 桌面

更新：2026-10-20。平板 Termux 的 `~/COMMANDS.md` 与本表一致。

## 启动与使用

以下在普通 Termux 执行：

```sh
ubuntu-manager start
ubuntu-manager connect
ubuntu-manager status
ubuntu-manager logs
```

唯一桌面路径是 Termux:X11 :8，窗口标签 gpu-test，OpenGL 默认使用 Virpipe → ANGLE → Android Vulkan → Mali-G925。打开 Termux:X11 即可使用；系统可能阻止后台自动拉起窗口。

`~/xfce/start.sh`、`connect.sh`、`status.sh`、`logs.sh` 仍可用，均转到同一个管理器。`ubuntu-desktop` 也启动同一路径。旧 `ubuntu-gpu` 和 `ubuntu-xfce-gpu` 仅保留为兼容转发入口，不再各自管理服务。

原 VNC 桌面已关闭，启动器不再启动 VNC；AVNC 5901 不再是连接方式。系统内旧 VNC 软件包和文件未卸载。

## 停止、重启和分辨率

保存桌面里的工作后再执行：

```sh
ubuntu-manager stop
ubuntu-manager restart
```

停止操作关闭对应的 XFCE、Termux:X11 :8 与 VirGL 服务，不结束其他显示或全局 PRoot 进程。

```sh
ubuntu-manager size 1600x1067
```

调整 Termux:X11 自定义分辨率，也可直接在该 Android 应用的设置里调整。没有修改 Android 系统屏幕分辨率或刷新率。

## 安装软件与图形终端

安装软件：

```sh
ubuntu-manager shell
apt update
apt install 软件包名
```

这个 shell 是镜像内管理员身份，无须 sudo；不是 Android Root。

进入继承当前图形会话和 GPU 环境的普通用户终端：

```sh
ubuntu-manager gpu-shell
```

从普通 Termux 启动图形程序：

```sh
ubuntu-manager run glxgears -geometry 800x600
```

按需软件绘图兼容某个程序：

```sh
ubuntu-manager software 程序名
```

软件兼容仅影响该次程序启动，不创建另一条桌面启动路径。`exit` 返回 Termux。

## 桌面应用

Ubuntu 桌面终端中：

```sh
code-tablet
chrome-tablet
firefox-tablet
dsh-web
fcitx5-configtool
```

Fcitx5 使用 Ctrl+空格切换。Harness 使用默认浏览器并校验本机认证链接。浏览器和 VS Code 保留原来的 PRoot 兼容参数；并非全部应用、所有视频解码都已启用 GPU。

GPU 链路已实际绘图验证，但短测没有证明整体帧率提升。窗口合成关闭，移动和缩放采用轮廓以减少重绘。配置位于 `~/.config/y900-xfce-gpu`，数据、应用和项目保持原样。GNOME 未恢复。

## 连接与备份

电脑需要连接时，在普通 Termux 执行：

```sh
sshd
```

若 PATH 异常：`/data/data/com.termux/files/usr/bin/sshd`。SSH 设备端口 8022；电脑通过 USB ADB 转发连接，不公开私钥。

说明备份：`~/.local/share/y900-backup/COMMANDS.md`。本次合并前脚本备份位置记录在：

```sh
cat ~/.local/state/y900-xfce-gpu/unify-backup-path
```

幻影进程限制上次设置为 `activity_manager/max_phantom_processes=2147483647`、`settings_enable_monitor_phantom_procs=false`，本次未改动。重启或厂商更新后如失效，仍须电脑 ADB 检查；普通 Termux 无法自行写入系统设置。
