## 2. 2026-10-17：第一次软件/硬件对照

### 软件渲染基线（llvmpipe）

```text
GL_RENDERER:    llvmpipe (LLVM 20.1.2, 128 bits)
GL_VERSION:     4.5 (Compatibility Profile) Mesa 25.2.8-0ubuntu0.24.04.4
[build]   duration=5: FPS: 146 FrameTime: 6.881 ms
[texture] duration=5: FPS: 145 FrameTime: 6.929 ms
[shading] duration=5: FPS: 137 FrameTime: 7.315 ms
glmark2 Score: 141
CPU test exit: 0
```

### GPU 路径（virpipe → ANGLE → Vulkan → Mali-G925）

```text
GL_RENDERER:    virgl (ANGLE (ARM, Vulkan 1.3.278 (Mali-G925-Immortalis MC1...)
GL_VERSION:     2.1 Mesa 25.2.8-0ubuntu0.24.04.4
[build]   duration=5: FPS: 138 FrameTime: 7.267 ms
[texture] duration=5: FPS: 160 FrameTime: 6.262 ms
[shading] duration=5: FPS: 125 FrameTime: 8.031 ms
glmark2 Score: 140
GPU test exit: 0
```

### 判读

- **renderer 明确不同**：`llvmpipe` vs `virgl (ANGLE ... Mali-G925)`，说明 GPU 路径确实被走到；
- **分数几乎相同**（141 vs 140）：说明这组短测**没有**证明 GPU 更快；
- `GLX_EXT_swap_control` 不可用，结果可能被刷新率截顶；
- 两次都退出码 0，三场景完整跑完。

## 3. 2026-10-20：第二次对照

```text
Screen 0: minimum 1 x 1, current 1280 x 1024, maximum 32767 x 32767
screen connected 1280x1024+0+0 0mm x 0mm
   1280x1024     29.90* 
false                                    # xfwm4 /general/use_compositing
```

| 场景 / 总分 | 软件（llvmpipe） | GPU（virpipe/Mali） |
|---|---|---|
| build FPS | 99 | 89 |
| texture FPS | 117 | 95 |
| shading FPS | 75 | 102 |
| **glmark2 Score** | **96** | **94** |

`glxgears -info` 同次输出：

```text
GL_RENDERER   = virgl (ANGLE (ARM, Vulkan 1.3.278 (Mali-G925-Immortalis MC1...)
GL_VERSION    = 2.1 Mesa 25.2.8-0ubuntu0.24.04.4
GL_VENDOR     = Mesa
679 frames in 5.0 seconds = 135.726 FPS
```

### 判读

- 这次 GPU 总分（94）**低于**软件（96），同样不支持「整体提速」；
- 归档说明指出当次存在其他 Android 图形负载与后台调度影响；
- `xrandr` 报告 `29.90`，那是名义模式频率，**不能**当作真实呈现帧率；
- 窗口合成已关闭（`use_compositing=false`），移动/缩放用轮廓，属于减少重绘而非「全面加速」。

## 4. 两次测试共同证明 / 不证明什么

### ✅ 证明

1. Ubuntu ARM64 内的 Mesa 可以经 `virpipe` 把 OpenGL 命令送到 Termux 侧的 `virgl_test_server_android`；
2. 该服务用 `--angle-vulkan` 时，最终落到 Android 原厂 Vulkan 驱动与 Mali-G925；
3. `glmark2` 与 `glxgears` 能在 `:8` 的 `gpu-test` 窗口里正常绘图并退出；
4. PRoot 的 `--shared-tmp` + VirGL socket、Termux:X11 的 `-extension MIT-SHM` 组合可用。

### ❌ 不证明

1. 整个桌面 / 所有应用都已硬件加速；
2. 桌面帧率、交互延迟全面提升；
3. 视频解码走硬件；
4. 浏览器、VS Code、游戏等具体应用都默认走 GPU（它们有各自开关）；
5. 独立 Geeks3D GpuTest 可用（本机根本没有该程序）。
