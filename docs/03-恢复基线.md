# 03 · 恢复基线（设备原镜像仍在时优先）

本页对应两条路径：

- **§1–§3：已有 `ubuntu` 容器** ← 推荐，风险最低；
- **§4：从空环境重建** ← 可选、高风险、本轮未实机验证。

> ⚠️ 恢复脚本只安装文件，不启动桌面；启动是单独一步。任何 `remove` / `reset` / `reinstall` 都会销毁现有容器，不要执行。

---

## 1. 先只读核对

在**普通 Termux**（不是容器内）：

```sh
proot-distro list
command -v ubuntu-manager
ubuntu-manager status
command -v termux-x11 virgl_test_server_android
```

判断：

- `proot-distro list` 里应有 `ubuntu`，状态 `installed`；
- 若 `ubuntu-manager` 已存在且 `status` 显示「运行中」，先按 §3.4 正常停止并保存工作；
- 若设备装的是 AVNC 分支管理器，`start` / `x11` 冷启动可能先报 VNC 错误，**这不代表 GPU 链路坏了**。目标若是恢复已验证的 X11/GPU 测试，请直接用本仓库基线覆盖，不要先修 AVNC。

---

## 2. 把仓库放进 Termux HOME 并校验

```sh
cd "$HOME/y900-termux-gpu-guide"     # 按实际解压/克隆位置填写
sha256sum -c SHA256SUMS
```

预期每个文件都是 `OK`。若从 Android 下载目录复制：

- 用已授权的共享存储或电脑 SSH 复制进 `$HOME`；
- 不要用会转成 CRLF 的编辑器；`file scripts/termux/ubuntu-manager` 不应出现 `CRLF`。

---

## 3. 恢复脚本

### 3.1 前置条件

- 在**普通 Termux**，`$PREFIX` 已设置；
- `ubuntu` 容器存在，且容器内 `/home/desktop` 存在；
- `python`、`proot-distro`、`termux-x11`、`virgl_test_server_android`、`pulseaudio`、`pactl` 都在 PATH；
- 当前**没有** `xfce4-session` 在运行（脚本会检查并拒绝）。

### 3.2 执行

```sh
bash scripts/restore-x11-baseline.sh
```

脚本会：

1. 校验 `PREFIX`、rootfs、`desktop` HOME；
2. 逐个检查依赖命令，缺失即报错退出；
3. 扫描 `/proc`，发现 `xfce4-session` 就拒绝继续；
4. 在容器内确认 `xfce4-session`、`xfconf-query`、`dbus-run-session`、`xdpyinfo`、`glmark2`、`glxgears` 存在；
5. 把将被覆盖的文件备份到
   `~/.local/share/y900-backup/archive-restore-<YYYYmmdd-HHMMSS>-<PID>/`
   （分 `termux/`、`ubuntu/`、`config/`）；
6. 安装 `scripts/termux/*` → `$PREFIX/bin/`，`scripts/ubuntu/*` → `$ROOTFS/usr/local/bin/`（`0755`）；
7. 安装 `config/xfconf/*.xml` → 容器的 `~/.config/y900-xfce-gpu/xfce4/xfconf/xfce-perchannel-xml/`（`0644`）；
8. 确保容器内 `~/.config/xfce4` 与 Termux `~/xfce` 目录存在；
9. 重新生成 `~/xfce/{start,connect,stop,restart,status,logs}.sh`，全部转发到 `ubuntu-manager`。

### 3.3 不会做的事

- 不启动 / 停止任何桌面或服务；
- 不修改 rootfs 其余数据、账号凭据、项目文件、浏览器资料；
- 不安装 AVNC 相关脚本，不启动 x11vnc；
- 不改 Android 系统设置。

### 3.4 停止后再恢复

若桌面正在运行，先在桌面里保存工作，然后：

```sh
ubuntu-manager stop
```

确认输出了「GPU XFCE 与对应 X11/VirGL 服务已停止」再执行恢复脚本。

---

## 4. 从空环境重建（可选，高风险）

> **现有 `ubuntu` 容器还在时跳过本节。** 以下步骤不在 2026-11-09 本轮做过实机重装验证；未来软件源版本会变化，本仓库也不含 rootfs 或 APK。

### 4.1 Termux 与 APK

1. 使用与既有 Play 版 Termux 相容的来源，安装 **Termux:X11 官方普通 APK** 与 Termux companion 包；
2. 当前 Play 版**不能**套用只适配 GitHub 同签名 Termux 的 `sharedUid` APK；
3. **不要卸载现有 Termux 来换来源**（会导致 `com.termux` 数据丢失）。

### 4.2 Termux 依赖

```sh
pkg install python proot proot-distro pulseaudio
pkg install termux-x11-nightly virglrenderer-android angle-android vulkan-loader-android
```

若找不到包：先核对 Play 分支源、`pkg search`，必要时按当前来源要求启用 `x11-repo`。**不要**替换成 Adreno / Turnip 或第三方 ICD。

### 4.3 创建容器

仅在确认**没有**名为 `ubuntu` 的容器时：

```sh
proot-distro install --name ubuntu ubuntu:24.04
```

当前 `proot-distro 5.3.0` 的 `install` 接受 Docker/OCI 镜像或 rootfs tarball，具体语法见 [`metadata/proot-install-help.txt`](../metadata/proot-install-help.txt)。也可使用可信的 Ubuntu ARM64 rootfs tarball——本仓库不附带镜像。

### 4.4 准备镜像依赖与 desktop 用户

在普通 Termux 的仓库根目录执行（把归档挂进容器）：

```sh
TASK_UID=$(id -u)
proot-distro login ubuntu --shared-tmp --no-sysvipc \
  --bind "$PWD:/mnt/y900-archive" -- \
  env Y900_UID="$TASK_UID" /bin/bash /mnt/y900-archive/scripts/prepare-ubuntu.sh
```

说明：

- `Y900_UID` 必须是**当前 Termux 的实际 UID**（本机为 `10309`），不是硬编码常量；
- 若容器内已有 `desktop` 但 UID/GID 不匹配，脚本报错退出，不自动改用户；
- 脚本安装 XFCE、`dbus-x11`、`mesa-utils`、`glmark2-x11`、`libgl1-mesa-dri`、CJK 字体、`fcitx5` 等；
- 首次使用 Fcitx5 可能需要在桌面设置里添加拼音；本仓库不迁移个人词库。

### 4.5 回到 Termux 装基线并启动

```sh
cd "$HOME/y900-termux-gpu-guide"
bash scripts/restore-x11-baseline.sh
ubuntu-manager start
```

首次启动会自动创建 `~/.config/y900-xfce-gpu`、`~/.cache/y900-xfce-gpu`、`/tmp/runtime-y900-xfce-gpu`，并从 `~/.config` 复制基础 XFCE 配置。

---

## 5. 启动后的自检

```sh
ubuntu-manager status
```

应看到：

```text
GPU XFCE：运行中
显示：Termux:X11 :8 / gpu-test；绘图：Virpipe → ANGLE → Mali；不启动 VNC。
VirGL：运行中
```

再确认 socket 与显示：

```sh
test -S "$TMPDIR/y900-gpu-vtest" && echo socket-ok
proot-distro login ubuntu --user desktop --shared-tmp --no-sysvipc -- \
  env DISPLAY=:8 xdpyinfo | head -5
```

然后进入 [05-测试与验收](05-测试与验收.md)。

---

## 6. 停止与清理

```sh
ubuntu-manager stop
```

- 关闭的是**这个基线桌面**对应的 XFCE、`termux-x11 :8`、VirGL 进程；
- 不会结束其他显示、`dbus-daemon` 或整机 PRoot；
- 不要在用户还开着文件时自动 `restart`；
- 合并后的 `ubuntu-gpu stop` 也会转到同一停止操作，不再只是停一个孤立测试服务。

如需回滚到恢复前的脚本，从 `~/.local/share/y900-backup/archive-restore-*/` 取回对应文件手动覆盖；脚本不会自动回滚。
